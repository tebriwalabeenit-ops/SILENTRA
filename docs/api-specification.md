# SILENTRA — REST API & WebSocket Protocol Specification

## 1. REST API Architecture

The backend REST API is hosted on FastAPI with OpenAPI 3.1 autogenerated documentation (`/docs` and `/redoc`).
- **Base URI**: `/api/v1`
- **Content-Type**: `application/json`
- **Authentication**: JWT Bearer Tokens in HTTP `Authorization: Bearer <token>` header.
- **Roles**: `ADMIN`, `LIBRARIAN`, `VIEWER`.

---

## 2. API Endpoint Resource Groups

### 2.1. Authentication & System
| Method | Endpoint | Access | Description |
|---|---|---|---|
| `POST` | `/api/v1/auth/login` | Public | Authenticate user and receive JWT access token |
| `GET` | `/api/v1/auth/me` | Authenticated | Retrieve current user profile and role permissions |
| `GET` | `/api/v1/system/health` | Public | Healthcheck for DB, MQTT broker, and memory stats |
| `GET` | `/api/v1/system/mode` | Public | Returns current runtime mode (`HYBRID`, `HARDWARE_ONLY`, `SIMULATION_ONLY`) |
| `POST` | `/api/v1/system/mode` | Admin | Dynamically switch operational runtime mode |

### 2.2. Floors & Spatial Geometry (2D/3D Single Source of Truth)
| Method | Endpoint | Access | Description |
|---|---|---|---|
| `GET` | `/api/v1/floors` | Public | List all active library floors with summary metrics |
| `POST` | `/api/v1/floors` | Admin | Register new floor with architectural dimensions |
| `GET` | `/api/v1/floors/{id}` | Public | Get full floor details including raw `floor_geometry` (2D layout JSON) |
| `PUT` | `/api/v1/floors/{id}` | Admin | Update floor parameters and 2D CAD boundary JSON |
| `GET` | `/api/v1/floors/{id}/zones` | Public | List all zones located on the specified floor |
| `POST` | `/api/v1/floors/{id}/zones` | Librarian | Create or modify zone polygon, type, and noise threshold |

### 2.3. Seats & Real-Time Occupancy
| Method | Endpoint | Access | Description |
|---|---|---|---|
| `GET` | `/api/v1/seats` | Public | List seats with query filters (`floor_id`, `zone_id`, `status`, `has_power`) |
| `GET` | `/api/v1/seats/{id}` | Public | Retrieve individual seat details, sensor link, and current session |
| `POST` | `/api/v1/seats` | Admin | Create seat with spatial coordinates $(x, y, \theta)$ |
| `PUT` | `/api/v1/seats/{id}/position` | Admin | Update seat coordinates (syncs 2D floor plan & 3D scene) |
| `POST` | `/api/v1/seats/{id}/override` | Librarian | Manual override for maintenance or reservations |

### 2.4. Acoustic Monitoring & Noise Heatmaps
| Method | Endpoint | Access | Description |
|---|---|---|---|
| `GET` | `/api/v1/noise/zones/current` | Public | Current $L_{Aeq}$ decibel readings across all library zones |
| `GET` | `/api/v1/noise/zones/{id}/history`| Public | Historical noise time-series for trend charts (1h, 24h, 7d) |
| `GET` | `/api/v1/noise/floor/{id}/heatmap`| Public | Interpolated grid data points for 2D/3D noise heatmap rendering |

### 2.5. Headcount & Entry/Exit Portals
| Method | Endpoint | Access | Description |
|---|---|---|---|
| `GET` | `/api/v1/headcount/live` | Public | Real-time net headcount breakdown (Total in building, per-floor) |
| `GET` | `/api/v1/headcount/flow` | Public | Rate of arrivals vs departures over time intervals |

### 2.6. Alerts & Librarian Notifications
| Method | Endpoint | Access | Description |
|---|---|---|---|
| `GET` | `/api/v1/alerts` | Librarian | List open alerts (`NOISE_VIOLATION`, `SENSOR_FAULT`, etc.) |
| `POST` | `/api/v1/alerts/{id}/ack` | Librarian | Acknowledge alert and record responder identity |
| `POST` | `/api/v1/alerts/{id}/resolve`| Librarian | Mark alert as resolved with optional notes |

### 2.7. Device Hardware Management & Sensor Mapping
| Method | Endpoint | Access | Description |
|---|---|---|---|
| `GET` | `/api/v1/devices` | Admin | List all registered microcontrollers, IP, RSSI, and status |
| `POST` | `/api/v1/devices/register` | Admin | Register new ESP32 board MAC address and name |
| `GET` | `/api/v1/devices/{id}/pins` | Admin | Inspect active GPIO pin sensor mappings |
| `POST` | `/api/v1/devices/{id}/assign` | Admin | Bind a physical pin (e.g. GPIO 14) to a logical seat or gate |

## 3. Real-Time WebSocket Specification

WebSocket connections provide bi-directional, push-based synchronization to prevent HTTP polling overhead.

- **WebSocket URL**: `ws://<host>:<port>/api/v1/ws`
- **Protocol**: JSON-formatted event frames.
- **Heartbeat**: Ping/Pong every 30 seconds.

### 3.1. Client $\rightarrow$ Server Subscription Message
Clients can subscribe to specific floors or event domains:

```json
{
  "action": "subscribe",
  "client_id": "web-client-8812",
  "filters": {
    "floor_id": "FL-01",
    "topics": ["occupancy", "noise", "headcount", "alerts"]
  }
}
```

### 3.2. Server $\rightarrow$ Client Broadcast Events

#### Event: `SEAT_STATUS_CHANGED`
Emitted immediately when a seat changes occupancy state.

```json
{
  "event": "SEAT_STATUS_CHANGED",
  "timestamp": "2026-11-20T01:38:05.120Z",
  "payload": {
    "seat_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
    "seat_code": "FL01-ZNA-S001",
    "floor_id": "FL-01",
    "zone_id": "ZN-01A",
    "previous_status": "AVAILABLE",
    "current_status": "OCCUPIED",
    "occupied_since": "2026-11-20T01:38:05.120Z",
    "data_origin": "HARDWARE"
  }
}
```

#### Event: `NOISE_TELEMETRY_UPDATE`
Emitted periodically or on threshold breaches.

```json
{
  "event": "NOISE_TELEMETRY_UPDATE",
  "timestamp": "2026-11-20T01:38:10.000Z",
  "payload": {
    "zone_id": "ZN-01A",
    "floor_id": "FL-01",
    "decibel_spl": 58.4,
    "peak_spl": 71.0,
    "threshold_limit_db": 55.0,
    "is_violation": true,
    "data_origin": "HARDWARE"
  }
}
```

#### Event: `HEADCOUNT_UPDATED`
Emitted on entry or exit gate passage.

```json
{
  "event": "HEADCOUNT_UPDATED",
  "timestamp": "2026-11-20T01:38:12.800Z",
  "payload": {
    "floor_id": "FL-01",
    "total_in_library": 86,
    "floor_occupancy": 34,
    "floor_capacity": 50,
    "occupancy_percentage": 68.0,
    "recent_event": {
      "direction": "IN",
      "gate_id": "FL01-GATE-MAIN"
    }
  }
}
```

#### Event: `ALERT_TRIGGERED`
Emitted when an operational alert is created.

```json
{
  "event": "ALERT_TRIGGERED",
  "timestamp": "2026-11-20T01:38:15.000Z",
  "payload": {
    "alert_id": "123e4567-e89b-12d3-a456-426614174000",
    "alert_type": "NOISE_VIOLATION",
    "severity": "WARNING",
    "zone_id": "ZN-01A",
    "zone_name": "Quiet Study Carrels",
    "message": "Continuous noise level of 68.4 dB exceeded threshold (55 dB) for > 15 seconds.",
    "is_acknowledged": false
  }
}
```
